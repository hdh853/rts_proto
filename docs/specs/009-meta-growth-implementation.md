# 레벨 강화·등급 진화 명령과 비용 조회

승인 근거: [007 통합 설계](007-meta-progression-system.md). 첫 기반 PR 병합 후 다음 단계 진행 요청에 따른 구현이다. 기준 main: f3e15ee. 브랜치: feature/meta-growth.

## 완료 범위

`GetGrowthQuote(cardId, raceStone)`는 저장을 바꾸지 않고 현재 revision, 레벨/등급/상한, 다음 행동, 보유·필요 재료, 실행 가능 여부와 차단 이유를 반환한다. quote 객체를 바꾸어도 저장이나 실제 차감에 영향을 주지 않는다. `raceStone`은 진화에만 쓰며, 생산카드는 생략 시 해당 종족, 공용 카드는 명시적 선택이 필요하다. UI 연결 시 현재 선택 종족을 공용 카드의 기본 입력으로 전달한다.

| 행동 | 차감 | 결과 |
|---|---|---|
| UpgradeCard | 동일 카드 + 스톤 | 레벨1 상승, 등급 유지 |
| EvolveCard | 한 종족의 종족스톤만 | 등급1 상승, 레벨 유지 |
| 최대 성장 | 없음 | 명령 거절, 다음 수치와 비용은 현재/0 |

N Lv4/R Lv9/SR Lv16/SSR Lv26에서는 진화 전 다음 레벨 강화가 불가능하다. 카드별 상한이 먼저 오면 성장이 종료된다. 광산 SR Lv16, 울타리 SSR Lv26, 생산카드 UR Lv36~41 등의 상한을 공통으로 적용한다.

종족스톤은 서로 섞어 지불할 수 없다. 휴먼 생산카드에 오크 종족스톤을 쓸 수 없다. 공용 카드 성장은 한 개 인벤토리에 기록되므로 다른 종족으로 조회해도 유지된다. 레벨 강화와 진화 모두 미해금 카드에는 적용할 수 없다.

## 거래와 재시도

기반 PR의 Execute 경로에서 요청 시점의 revision을 검증하고 비용을 다시 계산한다. 카드/재화 변경과 결과 영수증은 하나의 저장으로 확정한다. 저장 실패는 원래 상태를 보존한다. 같은 명령ID·입력의 재요청은 최초 결과를 반환한다. 뒤에 다른 강화가 일어났어도 최초 요청 당시의 레벨·등급·차감 재료를 반환한다.

기존 schema2 Receipt에 nullable `growth` 결과를 추가했다. 구 상자 영수증과 이전 저장 구조는 유지한다. 이전 PR의 최근128개 영수증/revision 정책을 그대로 사용하며 서버 명령 만료 정책을 구현했다고 주장하지 않는다.

## 수치 조회

레벨 배율은 `1 + 0.02 × (레벨-1)`이다. 기준 수치에 곱하는 체력/피해/지속시간 배율을 나눠 반환한다. 광산과 울타리는 체력만, 피해 마법은 피해만, 격려·채굴 마법은 지속시간만 상승한다. 소득, 생산주기, 공격주기, 사거리 배율을 노출하거나 일괄 상승시키지 않는다. 실제 전투 T1~T4의 기준 스탯에 적용하는 작업은 전투 스냅샷 연결 PR에서 수행한다.

진화는 레벨을 유지하므로 이 배율을 올리지 않는다. `skillEffectsAvailable=false`로 개별 등급 스킬 미구현 상태를 명시한다. 이번 PR은 성장 거래 기반이며 스킬 해금을 완성한 플레이 기능이 아니다.

## 후속 연결

PrototypeGame/기존 ProgressStore는 이번에도 전환하지 않는다. 다음 전투 연결 단계에서 한 번만 저장 이전하고 구 경제 쓰기를 종료하며 BattleLoadoutSnapshot으로 판 내부 성장값을 고정한다. 이후 메인·덱·상자 UI에서 이 조회/명령 API를 사용한다. 별도의 신규 확률이나 비용은 도입하지 않았다.
