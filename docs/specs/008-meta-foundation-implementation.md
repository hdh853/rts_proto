# 메타게임 기반 구현 — 첫 PR

상위 설계: [007 승인 명세](007-meta-progression-system.md). 사용자 승인: “설계 승인. 다음 단계 진행할것”. 기준 브랜치: origin/main dfa6260. 구현 브랜치: feature/meta-foundation.

## 완료 범위

- 승인된 20종 카드 성장 상한·성장 항목, 40단계 비용, 상자5등급 확률/보상 데이터를 Unity 배열 JSON으로 제공한다. Tools/export_meta_economy.py --check로 승인 원본과 일치 여부를 검사한다.
- Unity에 의존하지 않는 상태/규칙/명령 서비스와 시간·난수·저장 인터페이스를 추가한다.
- 신규 계정은 두 종족 기본덱을 해금하고 강화용 재화/중복카드는 지급하지 않는다.
- schema1 원본과 최초 이전 백업을 보존하고 schema2 별도 파일로 이전한다. 기존 스톤과 카드20종 사용권, 유효한 덱, 이전 챕터 기록을 보존한다. Lv1/2/3/4/5는 Lv1/3/4/6/7로 이전한다.
- 로컬 검증용 전투 시작/완료에서 한 전투만 활성화하고 빈 상자 슬롯을 예약한다. 만석 시작은 동의를 요구하며 이후 슬롯이 비어도 새 상자를 지급하지 않는다. 첫 챕터12스테이지만 보상 접근을 허용한다.
- 상자 획득 시 보상을 고정한다. 수동 개봉, 완료 미수령 상태, 동시 작업1개, 수령과 슬롯 제거를 단일 저장으로 처리한다.
- 카드 최초 해금·최대 성장 중복 변환과 영웅 조각/완전체 중복 처리를 구현한다. 영웅을 실제 전투에서 선택하는 기능은 후속 범위다.
- 명령 ID/내용 재요청, revision 충돌, 저장 실패를 처리한다. 최근128개 결과를 보존하며 소비된 상자ID는 새 명령으로도 재수령할 수 없다.
- 임시 파일 flush 후 원자적 교체와 이전 저장 백업, 배타적 로컬 쓰기 잠금, 손상 시 백업 읽기 및 양쪽 손상 시 초기화 거절을 제공한다.

## 실행 경계

이 PR은 **기반 코드 PR**이다. PrototypeGame/ProgressStore/전투 화면에 연결하지 않았다. 현재 실행 게임은 v0.5의 기존 보상과 화면을 유지한다. 새 경제를 사용했다고 표시하거나 기존 저장에 동시에 두 경제가 쓰도록 하지 않는다.

UnityMetaAdapter.Open(directory)는 명시적으로 실행하는 검증 진입점이다. 다음 PR에서 성장 명령과 UI/전투 어댑터를 연결할 때 기존 저장 쓰기를 끄고 한 번만 이전한다. 현재 게임 실행만으로 이전하지 않으므로 이전 이후에 구 저장이 바뀌는 충돌을 만들지 않는다.

전투 완료는 **로컬 테스트용 승리 입력**이다. 운영 서버 검증·전투 스냅샷 재현·인증·24시간 명령 만료·미개봉 보상 은닉 API는 구현하지 않았다. 로컬 파일과 시스템 시각은 조작 방지를 보장하지 않는다. 현재 Load 결과에는 테스트용 미개봉 보상이 포함되므로 서버 API에 그대로 노출해서는 안 된다.

상자에 저장된 경제 버전이 현재 정의와 다르면 시작/수령을 거절해 새 표로 조용히 계산하지 않는다. 운영 전에는 과거 버전 카탈로그 조회가 필요하다. UI 수령 연출에서 변환 전/후 차이를 보여 주는 응답 형식도 후속 UI 연결 시 추가한다.

## 검증

[테스트 방법과 결과](../testing-meta-foundation.md)를 따른다. .NET 기반 도메인 검사와 Unity 어셈블리 참조 컴파일은 완료했으며 Unity 에디터 실제 직렬화/Android 실행은 별도 검사다. 기존 전투 로직은 변경하지 않았다.
