# 메타게임 통합 시스템 설계 — 사용자 검토본

상태: 사용자 “설계 승인. 다음 단계 진행할것”으로 2026-09-13 승인 완료. 아래 규칙을 구현 기준으로 잠근다. 구현은 PR 단위로 나누며 실제 완료 범위는 PR 명세와 검증 기록에 따른다.

## 1. 앞으로의 작업 방식

사용자가 매번 작은 수치를 고르는 방식 대신, 설계자가 공식 레퍼런스 → 설계 대안 평가 → 하나의 권장안 선택 → 계산/검증 → 통합 검토본 순서로 제출한다. 기존 확정 규칙을 바꾸어야 할 때만 변경 이유와 영향을 별도로 표시한다. 승인 후 구현하고 PR로 검토하며 자동 병합하지 않는다.

전역 아트/UI 기준은 Clash Royale이다. 화면별 레퍼런스와 대표 샘플 검토를 거쳐 자체 모델·초상화·UI를 제작한다. 레퍼런스 게임의 규칙이나 최신 업데이트를 우리 게임의 확정 규칙에 자동 적용하지 않는다.

## 3. 승인된 기준 유지

- 8분 전투, 전투 골드/소울 판 종료 초기화. 메타 재화는 상자에서 획득.
- 상자5칸, 동시에1개만 개봉. 만석 시 사전 안내 후 전투 가능하지만 새 상자 없음.
- N/R/SR/SSR/UR 개봉시간: 5분/30분/2시간/6시간/12시간.
- 카드/스톤 확정 지급: N6/40, R20/140, SR60/500, SSR180/1600, UR500/5000.
- 종족스톤/영웅 조각/완전체는 승인된 확률로 독립 추첨한다. 승인 표는 006 명세를 따른다.
- 강화 횟수3/5/7/10, UR최대15. 영구 레벨당 기준 체력·공격력 +2% 선형 증가.
- 레벨 강화에는 동일 카드+스톤, 진화에는 종족스톤만 소비한다.
- 카드별 최대 등급/레벨은 다르다. 전투 T1~T4는 영구 성장과 독립. 광산 전투 합성 금지 유지.

## 4. 이번에 선택한 경제 규칙

### 4.1 강화/진화 비용

전체40단계 비용은 이 문서 뒤의 비용표와 경제_설계_기준값.json에 동일하게 기록한다. N의 첫3회는 동일 카드2/4/6장, 스톤20/40/80이다. 초기 카드 수집을 빠르게 경험하게 하고 후반에는 계단식으로 요구량을 높인다.

진화 비용: N→R 1개, R→SR 3개, SR→SSR 8개, SSR→UR 20개. 해당 종족스톤만 소모하고 일반 스톤/동일 카드 재료는 소모하지 않는다. 누적 UR 진화 비용은 종족스톤32개다.

생산 카드에는 해당 종족스톤을 사용한다. 공용 기능/마법 카드는 한 종류의 종족스톤을 선택해 전체 비용을 낸다. 서로 다른 종족스톤을 섞어 합산하지 않는다. 기본 선택은 현재 종족이며, 공용 카드 성장 상태는 종족을 바꿔도 공유한다. 진화 상세에서 소비할 종류를 명확히 확인한다.

### 4.2 카드 해금과 중복

- 신규 계정: 각 종족의 기본8장 덱은 사용 가능 상태로 지급. 초기 스톤/종족스톤/강화용 중복 카드는0. 두 종족의 공용 카드는 같은 소유 상태를 공유한다.
- 미보유 카드를 처음 받으면1장을 해금에 쓰고 나머지를 강화 재료로 보관. 카드가 해금되면 재료가0이어도 편성 가능하다.
- 카드 묶음 수: N2/R2/SR3/SSR4/UR5. 서로 다른 카드 ID를 균등 선택하고 총 지급량을 균등 분배한다. 풀의 카드 종류가 부족하면 반복 선택을 허용하되 지급 총량은 유지한다.
- 상자 안의 카드 ID는 획득 시 고정한 종족/스테이지 풀에서 선정한다. 영구 등급을 곧바로 올려 주는 카드 보상은 없다.
- 해당 카드가 최대 성장에 도달한 뒤 상자에서 추가로 받은 카드는1장당 스톤5로 자동 변환. 진행 중에는 중복 카드가 쌓여도 강제로 변환하지 않는다. 임의 판매/교환 기능은 첫 범위에 넣지 않는다.
- 상자에서 나온 보상의 변환이므로 별도의 전투 클리어 스톤 직접 지급은 부활시키지 않는다. 수령 화면에 변환 전 카드와 변환 결과를 표시한다.

### 4.3 카드별 최대 성장

| 계열 | 최대 등급 | 최대 레벨 |
|---|---|---:|
| H01 민병대 / O01 싸움터 | UR | 36 |
| H02 사격 훈련소 / O02 투척 훈련장 | UR | 38 |
| H03 기마대 / O03 주술 제단 | UR | 40 |
| H04 마법 연구소 / O04 파쇄 공방 | UR | 41 |
| H05 장창 훈련소 / O05 늑대 우리 | UR | 36 |
| H06 연발 쇠뇌소 / O06 바위 투척장 | UR | 38 |
| mine 광산 / mining 채굴 마법 | SR | 16 |
| fence 울타리 / rally 전투 격려 | SSR | 26 |
| tower 화살타워 | UR | 36 |
| crossbow 석궁타워 / fire 화염 폭발 | UR | 38 |
| magicTower 마법타워 | UR | 41 |

생산 카드가 낮은 최대 등급 때문에 UR 능력에서 영구 배제되지 않도록 전부 UR까지 허용하고 최종 레벨로 차이를 둔다. 이는 종족의 생산속도/비용 곡선을 바꾸지 않는다. 개별 스킬의 유용성과 최종 카드 간 균형은 전투 검증에서 확인한다.

모든 카드는 첫 검증판에서 N Lv1로 출발한다. 광산 영구 레벨은 건물 체력만 증가시키며 수입/일꾼 상한/고용비는 바꾸지 않는다. 타워는 체력/피해, 울타리는 체력, 피해 마법은 피해를 성장시킨다. 전투 격려/채굴 마법은 지속시간에 +2% 선형 증가를 적용하고 배율·범위는 고정한다. 반올림은 계산 끝에서만 하며 UI는 실제 적용값을 보여 준다.

등급 능력 슬롯은 R에서 기본 능력, SR에서 개선, SSR에서 보조 능력, UR에서 최종 개선으로 구성한다. 개별 효과는 사용자 요구대로 별도 설계한다. 비어 있는 능력은 플레이용 배포에서 진화 보상으로 표시하지 않는다. 먼저 데이터/저장/검증용 성장 구조를 만들고 실제 능력을 연결한 뒤 성장 기능을 완성으로 판정한다.

## 5. 스테이지 진행 설계

- 종족마다 챕터 진도 분리. 카드/재화/상자 슬롯은 계정 단위이며 공용 카드 성장은 공유.
- 챕터는12스테이지, 6번과12번이 정예. 첫 정예는1-6이며 N등급 기본 덱으로 클리어 가능해야 한다. 레벨/등급 수치를 입장 조건으로 사용하지 않는다.
- 플레이 버튼은 선택 종족의 다음 미클리어 스테이지로 진입. 챕터 영역을 터치하면 이미 클리어한 스테이지의 재도전 목록을 연다. 메인에 테스트용 맵 선택 버튼을 다시 노출하지 않는다.
- 클리어한 일반/정예는 횟수·에너지 제한 없이 재도전 가능. 빈 상자 슬롯이 있을 때 매 승리마다 해당 종류 확률표로 상자1개. 첫 클리어 보너스나 확률 보정은 첫 버전에 추가하지 않는다.
- 만석 경고에 동의하고 진입한 전투는 전투 중 슬롯이 비더라도 상자 지급 대상으로 바꾸지 않는다. 빈 슬롯으로 진입하면 한 전투에 대한 보상 슬롯을 예약한다. 계정에서 동시에 보상 전투는1개만 허용한다.
- 스테이지별 보상 풀은 고정 데이터다. 1-1~1-12는 해당 종족 기본덱8종, 챕터2 이후는 그 종족 생산6+공용8=14종으로 확장한다. 해당 단계 풀은 획득한 상자에 기록하며 개봉 때 종족 변경/새 챕터 해금으로 바뀌지 않는다.
- 첫 구현 콘텐츠는 휴먼/오크 챕터1의12스테이지씩을 기존 평야/다리 지형에 배치·AI 조합으로 구성한다. 챕터2 풀과 이후 진행 구조는 데이터로 준비하되 새 콘텐츠가 완성되기 전 무한 챕터를 허위 노출하지 않는다.
- 영웅을 처음 영구 해금한 뒤 선택할 수 있는 던전 포함 분기 스테이지를 챕터2부터 둔다. 영웅 미보유 때문에 본선 진행이 막히지 않도록 본선은 일반 필드로 진행 가능하게 한다. 던전 적/보스 처치·소울10·일반 필드 소환 규칙은 유지한다.
- 전투 난이도는 성장 시뮬레이션으로 검증한 것이 아니다. 1-6 N덱 클리어, 1-12 N~R 덱 클리어를 수동/전투 시뮬레이션 승인 기준으로 둔다. 잘못된 난이도를 강제 성장 입장 제한으로 가리지 않는다.

## 6. 영웅 수집

첫 설계 범위는 휴먼 영웅1명/오크 영웅1명이다. 영웅별 조각30개로 해금한다. 완전체를 처음 얻으면 조각 없이 해금한다. 영웅 자체의 영구 레벨/장비 시스템은 추가하지 않고 기존 판 내부 경험치/레벨 초기화를 유지한다.

같은 영웅 완전체 중복은 조각30개 상당, 이미 해금한 영웅의 조각은1개당 스톤100으로 자동 변환한다. 완전체와 조각이 같은 상자에서 나오면 완전체 해금을 먼저 적용하고 조각을 변환한다. 완전체로 해금할 때 이전에 모은 해당 영웅 조각도 같은 비율로 변환한다. 조각으로 해금할 때는30개를 소비하고 초과분만 변환한다. 영웅 종류가 추가되어도 캐릭터별 조각 소유량을 분리한다.

메인 종족에 맞는 보유 영웅1명을 선택하며, 현재 판에 소환할 영웅 ID를 전투 시작 시 고정한다. 던전 소울 소환·사망 후 부활·판 내부 경험치는 영구 해금과 별개다. 향후 영웅 증가로 조각 풀이 넓어지면 현재 단일 영웅 모델의 획득 일수를 그대로 사용하지 않는다.

## 7. 상자 상태와 실패 처리

상태: Stored(보관) → Unlocking(개봉 작업) → Ready(시간 완료) → Claimed(수령 완료/슬롯 해제).

- 수동으로 상자1개를 골라 개봉 시작. 앱을 꺼도 시간이 경과한다. 완료되어도 보상은 자동 수령하지 않는다.
- 다음 상자 자동 시작 없음. 다만 Ready 상자는 작업을 끝낸 상태이므로 슬롯은 차지해도 다른 Stored 상자의 개봉을 수동 시작할 수 있다. 클라이언트는 서버 현재시각으로 Ready 상태를 계산하되 지급 판정은 서버가 다시 검사한다.
- 작업 도중 취소/중단/순서 교체/시간 단축/광고/유료 개봉 없음. 상자 종류별 확률과 남은 시간을 UI에 표시한다.
- 상자 지급 시 instanceId, stageId, faction, poolVersion, economyVersion, reward 결정값, 획득시각을 저장한다. 운영판 reward 결정값은 클라이언트에 노출하지 않는 서버 전용 데이터다. 재접속/재요청으로 보상이 다시 추첨되지 않는다.
- 개봉 완료 상태를 먼저 확인하고, 보상 지급·상자 제거·수령 기록을 한 저장 변경으로 처리한다. 저장 실패면 결과 연출을 완료하지 않고 동일 요청으로 재시도한다.
- 앱이 연출 중 종료되어도 재지급하지 않는다. 재접속 시 최근 수령 결과를 다시 보여 줄 수 있다. 보상이 만석으로 미지급되는 경우에도 챕터 클리어 자체는 기록한다.
- 앱 삭제/기기 변경까지 복구하는 것은 운영 서버 계정 저장 범위다. 로컬 검증판은 파일이 제거되면 복구할 수 없음을 구분한다.

## 8. 기술 시스템 구조

### 8.1 계층과 데이터

Unity 화면 계층 → MetaApplication 명령/조회 → 순수 C# MetaDomain 규칙 → 저장/시간/난수 어댑터로 분리한다. 현재 ProgressStore에 상자와 모든 규칙을 계속 추가하지 않는다. UI는 직접 재화 수량을 수정하지 않는다.

정적 데이터: CardDefinition(id/faction/kind/startRank/maxRank/maxLevel/growthStatPolicy/skillSlots), LevelCostTable, EvolutionCostTable, ChestDefinition, LootPoolVersion, StageDefinition, HeroDefinition.

동적 상태: schemaVersion/revision, stoneBalance, raceStoneBalances, cardStates(unlocked/copies/rank/level), heroStates(unlocked/shards), factionProgress, deck8, selectedHeroByFaction, chests5, activeBattle/reservation, 최근 명령 수령 기록.

전투 시작 시 덱8장 소유권·종족·중복 금지와 성장 데이터를 검증하고 BattleLoadoutSnapshot을 생성한다. 진행 중인 판의 성장값은 고정한다. 메타 강화로 이미 생성된 전투 유닛을 실시간 변경하지 않는다.

명령: BeginBattle, CompleteBattle, StartChestUnlock, ClaimChest, UpgradeCard, EvolveCard, SetDeck, SelectFaction, SelectHero. 모든 변경 명령에 commandId와 expectedRevision을 포함한다. 입력 검증 → 규칙 계산 → 하나의 새 상태 생성 → 저장 성공 → 결과 UI 순서다.

### 8.2 로컬 검증판

우선 로컬 파일 기반 어댑터로 핵심 순환과 UI를 검증한다. 기존 저장을 백업하고 새 파일 임시 쓰기/완료 후 교체, 실패 시 메모리 변경도 되돌린다. 이 단계는 경제 보안이 보장된 운영 빌드가 아니다. 테스트용 시간/재료 조작은 개발 빌드에서만 제공하고 사용자 메인 화면에 노출하지 않는다.

### 8.3 운영판

기술 방향은 Unity Authentication + Cloud Code + Cloud Save로 선택한다. 서버 UTC와 보호/비공개 데이터, write lock 기반 충돌 검사를 사용한다. 정산 기준 상태는 계정별 Private Custom Data의 단일 메타 상태로 두고, Cloud Code가 인증 컨텍스트의 계정 ID로만 접근한다. 조회 응답은 미개봉 보상/난수 값을 제거해 전달한다. 재화와 카드/상자 상태는 하나의 버전 관리 메타 상태로 처리하여 여러 서비스에 차감/지급을 나눠 쓰는 문제를 우선 피한다. Unity Economy의 비용/보상 모델을 참고하되 첫 구현에서 동일 잔액을 Economy와 Cloud Save에 이중 저장하지 않는다.

운영판 클라이언트는 읽기와 명령 요청만 수행한다. 직접 잔액/상자/성장 상태 쓰기를 허용하지 않는다. 충돌 시 최신 상태를 받아 표시하고 비용이 바뀐 거래를 자동 재실행하지 않는다. 같은 commandId/내용의 재시도는 기존 결과를 반환한다. 동일 commandId에 다른 내용을 넣으면 거절한다.

최근 응답 기록은 크기 제한을 둔다(초기128개). 일반 메타 명령은24시간 만료, 오래된 expectedRevision 재요청은 상태 확인을 요구하며 새 거래로 재적용하지 않는다. 종료/폐기된 상자ID로 다시 수령할 수 없다. 전투 토큰은30분 만료이며 동일 battleId 결과를 두 번 정산하지 않는다. 계정 초기 생성, 상태/보상 동시 변경의 원자성, 기록 만료 경계는 실제 서비스 통합 검사로 확인해야 한다. SDK가 자동으로 모든 거래를 원자 처리한다고 가정하지 않는다.

전투 승리값을 클라이언트가 보냈다는 이유만으로 보상을 지급하지 않는다. 서버가 발급한 전투 설정/시드/성장 스냅샷과 명령 기록을 검증하는 서버 재현 경로를 운영 전 필수 과업으로 둔다. 현행 Unity 의존 시뮬레이션을 그대로 Cloud Code에 배포할 수 있다고 가정하지 않으며, 순수 C# 전투 코어 분리와 플랫폼 간 재현 검증이 선행되어야 한다.

로컬 검증판 결과를 운영 서버의 안전성 검증으로 대체하지 않는다. 서버 서비스 생성/비용 발생/배포는 검토 후 별도 실행 단계다. 첫 개발 PR에서 외부 서비스를 자동 개설하지 않는다.

## 9. 이전 저장 정책

기존 테스트 진행을 자동 삭제하지 않는다. schema1 원본 백업 후 schema2로 이전한다. 기존 스톤은1:1 보존하고 새 카드 수량은0부터 시작한다. 기존에 자유롭게 사용 가능했던 카드20종은 이전 계정에서 해금 상태를 유지한다. 신규 계정의 기본8종/추가해금 정책과 구분한다.

기존 +3% 계열 레벨을 새 +2% 체계에서 낮추지 않도록 newLevel=1+ceil(1.5×(oldLevel-1))로 매핑한다. 기존 Lv1/2/3/4/5는 새 Lv1/3/4/6/7. Lv4 초과는 필요한 최소 등급R을 함께 부여하며 이전 재료는 청구하지 않는다. 이는 테스트 저장 이전의 보상 처리이며 신규 계정 경제에는 포함하지 않는다. 검토 화면에 이전 전/후 수치를 표시한다.

기존 스토리 3맵 완료는 별도 legacyCleared로 보관하고 새12스테이지를 임의 완료 처리하지 않는다. 덱은 소유/종족/8장 유효성을 검사하고 기존 유효 선택을 유지한다. 저장 실패 시 이전 완료 표식을 기록하지 않는다. 재실행해도 이전 보상이 중복 생성되지 않아야 한다. 기존 판 내부 영웅 경험치는 영구 저장으로 전환하지 않는다.

## 10. UI 설계 계약

- 메인: 상단 종족 → 챕터 진행 → 상자5칸 → 플레이. 하단은 메인/덱. 기존 성장 탭은 카드 상세로 통합. 맵 선택/연습/플레이 방법 버튼은 사용자 메인에서 제거.
- 상자칸: 이미지·등급·상태. 선택 시 개봉 시작/남은 시간/수령 중 하나만 주 행동으로 노출. 만석 경고는 플레이 전에 한 번 명확하게 표시.
- 덱: 상단8장, 아래 소유 카드 그리드. 이미지와 우측상단 전투 골드 비용. 레벨/등급/강화 가능 상태는 작은 배지로 표현. 긴 설명은 상세창으로 이동.
- 상세: 이름·역할·전투 티어별 보기·현재 영구 레벨/등급·현재/다음 스탯·보유/필요 재료·스킬 해금 목표. 카드 레벨 강화 버튼에는 동일 카드+스톤, 진화 버튼에는 종족스톤만 표시.
- 현재 슬롯을 선택한 뒤 상세에서 교체할 카드를 지정한다. 보유 카드 탭이 곧바로 기존 카드를 제거하는 동작은 없앤다. 상세의 편성 버튼과 강화 버튼은 분리.
- 영웅은 덱 화면의 별도 영웅 슬롯에서 선택한다. 덱8장에 영웅을 포함하지 않는다. 영웅 인벤토리는 상세에서 조각 진도를 보여 준다.
- 원래 목표인 Clash Royale 수준의 입체감과 버튼/카드 피드백을 대표 시안으로 검토한 후 제작. 문서만으로 비주얼 품질이 승인된 것은 아니다.

## 11. 검증과 PR 계획

설계 검토 후 데이터/저장 → 상자 거래 → 성장/영웅 → 챕터/전투 스냅샷 → 메인/덱 UI → 대표 아트/연출 순으로 PR을 나눈다. 실제 스킬 없이 진화 시스템을 플레이 완성으로 표시하지 않는다. 서버 전투 검증/계정 복구는 운영 전 별도 PR 묶음이다.

필수 검사: 확률 합/데이터 누락, 요구량 증가/상한, 0카드 진화, 동일 카드 차감, 공용 종족스톤 혼합 금지, 5칸 예약 경합, 완료 미수령+다른 개봉, 보상 중복 요청, 저장 실패와 재실행, 최초 해금/최대 카드 변환, 영웅 동시 조각·완전체, 마이그레이션 재시도, 레벨과 T4 분리, 상자 풀/버전 고정, 앱 시간 변경, 다중 기기 충돌, 오래된 명령 재전송.

실기기 기준: 기본 덱 첫 강화와 진화 안내 이해, 만석 무보상 입장 동의, 카드 골드와 스톤 비용 혼동 없음, 8장 교체/상세 오탭 없음, 개봉 완료 재접속 복구, 전투 성장 스냅샷 유지, 5슬롯/긴 개봉 대기 중 이탈 반응. 실제 승률/전투 길이로 경제 모델을 다시 보정한다.

## 14. 재현 가능한 경제 시뮬레이션

### 가정과 범위

총1,800개 모의 계정: 기본6그룹(접속3종×육성2종)과 민감도3그룹, 그룹별200개 시드, 각180일. 실제 유저 데이터가 아닌 조건부 모델이다.

- 하루40분: 08시/20시 각20분. 하루60분: 08시/13시/21시 각20분. 하루120분: 08시/12시/17시/22시 각30분.
- 기본 전투는 평균4분, 승률80% 고정. 제한시간8분과 평균 종료시간을 구분한다. 모든 전투가8분 걸리는 경우를 별도 계산했다.
- 로그인과 전투 종료 때 완료 상자를 수령하고 가장 오래된 상자를 수동 개봉한다고 가정한다. 오프라인 자동 시작은 없다. 이는 모델의 행동 전략이며 Ready 상자 수령이 다음 개봉의 필수 조건은 아니다.
- 기본은 여섯 번째 승리부터 정예 보상 접근, 이후 일반2:정예1 시도 비율. 첫12승 상자는8종, 이후14종 풀. 실제 챕터 진행·패배 위치·스테이지별 난이도를 재현하지 않은 단순화다.
- 집중 육성은 H01만 강화한다. 균등 육성은 기본덱8장 중 낮은 레벨부터 가능한 강화를 실행한다. 종족 전환 없이 한 종족스톤을 사용한다.
- 초기 강화 재화0, 기본8장 해금, 영웅 후보1명. 보장 횟수/광고/과금/무료 추가 보상 없음. 보상 난수는 모델에서 수령 시 생성하지만, 제품에서는 획득 시 고정한다. 재추첨 행동은 모델에 없다.
- 성장에 따른 승률 상승, 등급 스킬, 유저 이탈, 카드 교체 전략, 두 종족 동시 육성은 포함하지 않았다. 미래14종 풀 모델을 챕터1만 출시한 버전의 실제 결과로 주장하지 않는다.

### 결과를 반영한 설계 판단

1. **초기 비용은 이 안으로 선택한다.** 첫 R은 며칠, 덱 R은 약1주, 덱 SR은 수 주를 목표로 한다. 집중 육성의 첫 카드 UR 중앙값은 하루60분 기준 약124일이며 균등 육성보다 빠르다. 실기기 전투와 보상 수집 기록으로 출시 전 다시 보정한다.
2. **상자 대기가 성장의 주된 제약이다.** 4분 기본 조건은30일 동안 약217승에서 상자를 못 받는다. 8분 조건은 약7승이다. 오래 플레이해도 보상을 더 얻기 어려운 구간이 발생한다. 확정된5칸/동시1개 규칙은 유지하고 UI에서 무보상 입장을 명확히 알린다. 유지율이 나쁘면 슬롯이나 개봉 규칙 변경안을 별도 검토한다.
3. **정예 반복은 성장에 유리하도록 허용한다.** 같은 승률 가정에서 덱 SR은 약27일에서16일로 빨라진다. 따라서 약27일을 모든 플레이어의 목표값으로 쓰지 않는다. 정예를 안정적으로 이길 수 있게 된 보상으로 이 차이를 수용하며, 신규 카드 풀 해금은 본선 진행의 동기로 둔다. 정예의 실제 승률·전투시간을 확인하기 전 성장 속도가 확정됐다고 보지 않는다.
4. **최대 성장은 장기 목표다.** 기본6그룹에서 H01 최대Lv36 도달은180일 안에 관측되지 않았다. 집중 육성은 스톤이 남고 특정 카드가 부족해지는 반면, 균등 육성은 스톤 소비가 커진다. 선택 카드에 자원을 몰아도 즉시 최종 성장하지 않는 구조를 첫 안으로 선택한다. 수개월 플레이 경험은 이 모델만으로 품질을 보장할 수 없다.
5. **카드 풀 확대와 신규 영웅은 재검증 대상이다.** 보상량이 같아도 원하는 카드의 획득률은 달라진다. 풀 변경 때 기존 성장 일수를 인용하지 않고 같은 스크립트로 비교표를 갱신한다.

## 15. 산출물과 다음 단계

경제_설계_기준값.json은 수치 원본, 경제_시뮬레이션.py는 표준 라이브러리만 사용하는 재현 모델, 경제_시뮬레이션_결과.json은 실행 결과다. 세 파일을 같은 폴더에 두고 Python으로 스크립트를 실행하면 결과 JSON을 다시 생성한다. Python 버전과 난수 시드가 같아야 정확한 재현 비교가 가능하다.

설계 검토는 승인 완료했다. 첫 PR은 데이터/저장 이전과 상자 상태·거래를 구현한다. 이후 개별 능력과 대표 UI 시안을 자료 조사 후 별도 검토안으로 제출한다. 상자·성장 화면 전체가 실제 플레이로 검증되고 능력이 연결되기 전에는 메타게임 완성으로 보고하지 않는다.

이 문서의 경제 모델 검증은 Unity 게임 테스트나 Android 빌드 성공을 뜻하지 않는다. 구현 검증은 각 PR의 기록을 따른다.
