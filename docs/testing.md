# 프로토타입 0.2.0 실행·검증 안내

## 현재 확인한 결과

2026-09-12 Unity 6000.4.0f1 Windows 개발 빌드가 성공했다. Unity에서 핵심 규칙 자동 검사 30개를 통과했고, 실행 파일에서 편성·일반 전장·던전·T4 선택 화면을 저장했다. 이 검사는 아래 모든 수동 항목을 통과했다는 의미는 아니다. Android APK 빌드도 12:57에 성공했으며 패키지의 Android API 26 이상·ARM64 설정을 확인했다. 실기기 터치·성능 검증은 아직 완료되지 않았다. 화면 상단 기지 잘림 수정은 최종 Windows 실행 화면에서 확인했다.

## Windows에서 바로 플레이

1. 제공된 `BackpackRTS-Windows-0.2.0.zip`을 폴더 전체로 압축 해제한다.
2. `BackpackRTS.exe`를 실행한다. 함께 있는 `BackpackRTS_Data`, Unity DLL과 기타 파일을 분리하지 않는다. Unity 설치는 필요 없다.
3. 540×960 세로 창이 열린다. 휴먼 또는 오크를 고른다.
4. 6종 중 선택된 유닛의 **선택** 버튼을 눌러 빼고, 다른 유닛의 **추가** 버튼을 눌러 정확히 4종을 구성한다. 가격대 제한은 없다.
5. 처음에는 **01 평야 → 연습 모드**를 선택한다. 일반 모드보다 자원이 많고 검증 버튼이 있으며 영구 보상은 지급하지 않는다.

## 조작법

| 하고 싶은 일 | 조작과 기대 결과 |
| --- | --- |
| 병영·타워 건설 | 아래 카드 클릭 → 아군 평야의 빈 칸 클릭. 카드 우측 아래 도형이 점유 칸이다. 회전 불가. 실패하면 골드와 카드를 유지한다. |
| 금광 건설 | 금광 카드 → 아군의 비어 있는 금색 자원 영역 클릭. 일반 평야에는 불가하다. |
| 일꾼 구매 | 기존 금광 클릭 → `일꾼 + 비용G`. 티어별 정원까지 구매한다. |
| 무료 카드 교체 | 손패 우측 위 `새로고침` → 교체할 카드 1장. 사용 후 전투 시간 30초에 1회 회복한다. |
| 합성 | 완성된 건물 클릭 → `합성 대상 선택` → 같은 종류·티어의 다른 건물 클릭. 결과는 두 번째 건물 위치에 남는다. 빈 칸 이동은 불가하다. |
| T4 선택 | T3 두 개를 합치면 건물 위 버블이 열린다. 0.45초 이상 누르면 상세 설명, 짧게 눌러 확정한다. |
| 건물 판매 | 건물 클릭 → `판매`. 기지는 판매할 수 없다. 제공 시설은 환급액이 0이다. |
| 장애물 제거 | 카드·합성 선택을 해제한 상태에서 아군 장애물 클릭. 3골드를 사용한다. |
| 일시정지 | 우측 상단 `정지`. 양 필드, 교체, 생산, 부활 시계가 함께 멈춘다. |
| 전투 포기 | `정지 → 전투 포기`. 승리 보상은 없다. |

배치 후 유닛 생산·이동·공격은 자동이다. 유닛을 직접 이동시키는 조작은 없다. 유닛 생산 시간은 종류·티어에 따라 다르며 출구가 막히거나 인구 상한에 도달하면 대기한다.

## 10분 검증 순서

1. **편성**: 3종만 선택하면 출전 버튼이 비활성화되는지 확인한다. 4종으로 돌아온다.
2. **평야·배치**: 병영 카드를 놓는다. 같은 점유 칸·중립·적 구역에 잘못 놓았을 때 골드와 패가 보존되는지 확인한다. 생산까지 기다려 유닛이 자동 진군하는지 확인한다.
3. **교체**: `새로고침 → 카드`로 교체한다. 30초 전에 정지해 잔여 시간이 멈추는지, 재개 후 30초가 채워져 1회만 회복하는지 확인한다.
4. **합성**: 연습 전장에서 아무 건물도 선택하지 않은 상태로 `T3 재료`를 누른다. 생성된 같은 건물 둘을 선택 순서대로 합친다. 버블을 길게 눌러 설명을 확인한 뒤 짧게 눌러 분기를 확정한다. 공간 부족 시 다른 위치를 비우거나 연습을 새로 시작한다.
5. **두 다리**: 편성으로 돌아와 02번 맵에서 플레이한다. 강을 직접 건너지 않고 다리로 이동하는지, 병영 주변 통로가 확보되는지 확인한다.
6. **던전**: 03번 맵에서 `던전 필드` 탭을 누른다. 처음 존재하는 적은 수비병 4명과 보스 1기다. 아래 구역에 병영을 놓고 전투를 기다린다. 일반 필드에도 방어 병영을 지어야 기지가 버틴다. 일반·던전의 손패와 골드는 공유된다.
7. **소울**: 수비병만 죽었을 때 소울이 늘지 않고 보스 사망 시 10이 지급되는지 확인한다. 연습의 `자원 +`는 소울도 제공하므로 보스 보상 자체를 확인할 때 사용하지 않는다.
8. **영웅**: `영웅 소환 · 소울 10` → 일반 필드에서 영웅을 확인한다. `수호의 함성`을 바로 누를 수 있어야 한다. 처치 XP, 영웅 사망 후 20초 대기와 같은 레벨 부활을 확인한다. 출구·인구가 막히면 부활이 지연될 수 있다.
9. **영구 성장**: 일반 모드에서 승리한 뒤 에너지스톤 증가 → 편성의 `에너지스톤 성장` → 유닛 강화. 게임을 종료·재실행해 스톤·강화가 유지되고, 새 전투의 영웅 성장이 초기화되는지 확인한다. 연습에는 스톤 보상이 없다.
10. **종족 비교**: 같은 맵에서 휴먼과 오크를 각각 플레이한다. 오크의 높은 비용·느린 생산·강한 개체가 체감되는지 기록한다. 한두 판의 결과로 밸런스가 확정되었다고 판단하지 않는다.

## Android 테스트

대상은 Android 8.0 이상, ARM64 기기다. 출력 폴더의 `BackpackRTS-0.2.0.apk`로 아래 절차를 사용한다.

1. APK를 휴대전화로 복사해 파일 관리자로 연다. 해당 파일 관리자의 앱 설치 허용이 필요한 경우 Android 안내에 따라 허용한다.
2. 개발 PC에 USB 디버깅으로 연결했다면 `adb devices`에서 기기 연결을 확인하고 `adb install -r BackpackRTS-0.2.0.apk`로 설치할 수 있다.
3. 앱을 켜고 휴대전화를 가로로 돌려도 화면이 세로인지 확인한다. 노치·상단 상태 영역이 버튼을 가리지 않는지 확인한다.
4. 위 검증 순서를 터치로 반복한다. 특히 카드 선택, 작은 금광 선택, T4 길게 누르기, 필드 전환을 확인한다.
5. 전투 중 홈 화면으로 나갔다 돌아오면 일시정지 상태인지 확인하고 재개한다. 통화·화면 잠금 후에도 같은 절차를 확인한다.
6. 양 필드에 유닛이 쌓인 상태로 6분간 플레이해 프레임 저하·발열·터치 지연을 기록한다. 이 항목은 아직 실기기 검증 전이다.

## Unity에서 프로젝트 열기와 재빌드

Unity Hub의 **Add project from disk**로 `BackpackRTS` 폴더를 추가한다. 버전은 **6000.4.0f1**이다. Android 빌드에는 같은 버전의 Android Build Support, SDK·NDK Tools, OpenJDK가 필요하다. 처음 열 때 임포트가 끝나면 `Assets/Scenes/Boot.unity`를 열고 Play를 누른다. Game 뷰를 540×960 또는 9:16으로 설정한다.

메뉴 `Prototype/Validate rules`는 30개 검사를 실행한다. `Prototype/Build Windows` 또는 `Prototype/Build Android`는 설정과 검사를 거쳐 빌드한다. 결과는 각각 `Builds/Windows`와 `Builds/Android`다. Android 빌드는 IL2CPP·ARM64 개발 빌드이며 배포 스토어용 서명은 설정하지 않았다.

이 PC에서 사용하는 `android-local-paths.json`은 로컬 SDK 경로 설정으로 Git에서 제외한다. 다른 PC는 Hub의 기본 도구를 사용하거나 자신에게 맞는 외부 도구 경로를 설정한다. Unity는 실행 계정의 유효한 라이선스가 필요하다.

## 데이터 수정 위치

`Assets/Resources/balance.json`에서 유닛별 비용·형태와 T1/T2/T3/T4A/T4B 값을 수정한다. HP·공격력·공격간격·사거리·이동속도·생산주기·효과를 독립적으로 저장한다. 수정 후 에디터를 다시 실행하거나 다시 빌드한다. 기존 배포 exe 옆에 JSON을 두는 방식의 실시간 패치는 지원하지 않는다. 새 유닛은 고유 ID와 종족·5개 티어를 추가하면 편성 후보 데이터에 반영되지만, 현재 메뉴는 종족당 6칸이므로 추가 후보를 표시하는 스크롤 UI는 후속 명세가 필요하다.

## 로그·저장·문제 제보

Windows 저장 폴더는 `%USERPROFILE%\AppData\LocalLow\RTS Prototype\Backpack RTS`다. `progress.json`과 `.bak`에 성장을 저장한다. `Player.log`에서 실행 오류를 확인할 수 있다. 새 저장으로 시험하려면 앱 종료 후 저장 파일 두 개를 별도 폴더로 백업·이동한다. 다시 복원하면 기존 성장을 사용할 수 있다.

제보할 때 버전, 기기·OS, 종족·덱, 맵, 일반/연습, 재현 순서, 기대 결과와 실제 결과를 적는다. 가능하면 발생 직후 로그와 화면을 함께 보관한다. Android 앱 데이터 삭제·제거 시 로컬 성장은 사라질 수 있으므로 저장 유지 테스트와 구분한다.

## 알려진 한계

- 그래픽은 자체 제작한 절차 생성 카툰 블록·캐릭터다. 레퍼런스 수준의 완성된 캐릭터 아트·애니메이션·사운드는 아직 아니다.
- 밸런스 값과 종족 파워곡선은 초기 가설이다. 다양한 덱의 반복 대전·동일 투자·동일 면적 분석과 실기기 성능 측정은 후속 작업이다.
- 초기 AI, 격자 경로 탐색, 즉시 피해 판정으로 핵심 게임 순환을 검증한다. 다수 병력의 경로 최적화와 공격 연출은 개선 여지가 있다.
- 엘프·언데드·좀비, 협동·PvP, 스토리, 온라인 저장은 구현하지 않았다.
- 최초 프로토타입 이후에는 변경 명세 승인 후 브랜치·PR로 작업한다.
